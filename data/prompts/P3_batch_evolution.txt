You are a memory evolution agent. Revise the existing memory notes below given new information that is strongly related to them. Each existing note should be updated independently by merging its knowledge with the new note.

## Task
For EACH existing note, merge its keywords/tags/description with the new note's information and output an updated version. Each updated note keeps its own "id".

- **keywords**: Merge both lists, remove duplicates (case-insensitive), keep 3–10 most specific and informative.
- **tags**: Merge both lists, remove duplicates, keep all non-redundant labels.
- **description**: A 1–2 sentence synthesized factual summary integrating the new information. Do NOT simply concatenate the two descriptions.

## Rules per relationship
- The new note **contradicts** an existing note: the updated description reflects the corrected/current state; remove obsolete keywords for disproven facts.
- The new note **extends** an existing note: enrich the description with the new details; keep all keywords.
- The new note is **causal** to an existing note: mention both events and their connection in the description.

## Reasoning steps (think through these BEFORE outputting the JSON)
Step 1: For each existing note, compare it with the new note.
Step 2: Merge keywords and tags, deduplicating.
Step 3: Write the synthesized description.
Step 4: Check every note from the input has exactly one output object with its original id.

## Output Format
Your response must be ONLY the following JSON array (no markdown fences, no commentary):
[{{"id": "<note_id>", "keywords": [...], "tags": [...], "description": "updated summary"}}, ...]

## Examples

Example 1:
Existing notes: [{{"id": "n1", "keywords": ["alex", "data scientist"], "tags": ["professional"], "description": "Alex works as a data scientist."}}]
New note: {{"id": "n4", "keywords": ["alex", "google", "mountain view", "data scientist"], "tags": ["professional", "location"], "description": "Alex is a data scientist at Google in Mountain View."}}
Reasoning: The new note extends n1 with employer and location.
[{{"id": "n1", "keywords": ["alex", "data scientist", "google", "mountain view"], "tags": ["professional", "location"], "description": "Alex works as a data scientist at Google in Mountain View."}}]

Example 2:
Existing notes: [{{"id": "n1", "keywords": ["alex", "san francisco"], "tags": ["personal", "location"], "description": "Alex lives in San Francisco."}}, {{"id": "n2", "keywords": ["alex", "data scientist"], "tags": ["professional"], "description": "Alex works as a data scientist."}}]
New note: {{"id": "n3", "keywords": ["alex", "new york", "job", "move"], "tags": ["personal", "location", "professional"], "description": "Alex moved to New York for a new job."}}
Reasoning: n3 contradicts n1 (location) → corrected state. n3 extends n2 (job details) → enriched.
[{{"id": "n1", "keywords": ["alex", "new york", "job", "move"], "tags": ["personal", "location", "professional"], "description": "Alex moved to New York for a new job, having previously lived in San Francisco."}}, {{"id": "n2", "keywords": ["alex", "data scientist", "new york", "job"], "tags": ["professional", "location"], "description": "Alex works as a data scientist in New York, where he moved for a new job."}}]

## Common Mistakes (NEVER do these)
WRONG: Omitting a note, changing an id, or outputting only one object when several were given.
→ Every existing note gets exactly one updated object with its original id.

## Constraints
- Output ONLY the JSON array. Do NOT include any commentary, markdown fences, or extra text.
- Every existing note must appear in the output with its original "id".
- All three fields (keywords, tags, description) are required.
- Preserve each note's core identity — do not invent facts not present in the inputs.
